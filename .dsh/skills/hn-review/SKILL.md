# hn-review

## Когда

Проверка патча, PR, списка изменённых файлов перед merge/push.

## Запреты

- **Не редактировать файлы**, пока пользователь не сказал «исправь».
- Не предлагать массовый рефакторинг.
- Не расширять scope ревью за пределы переданного diff/списка.
- Не читать секреты, `.env`, ключи.

## Порядок

1. Список изменённых путей (от пользователя или git status/diff).
2. По каждому файлу — только подтверждённые проблемы с путём.
3. Разделить: **дефект** / **вопрос** / **не трогать**.
4. Итог: можно ли коммитить / что блокирует.

## Чеклист ревью

- [ ] id не столкнулись с существующими
- [ ] нет сырого русского в YAML name/desc
- [ ] locale-ключи есть для новых name/desc/popup
- [ ] маркеры `#HN` / `//HN` на чужих файлах
- [ ] слой верный (нет Server-логики в Client)
- [ ] слоты из канона, не выдуманы
- [ ] нет правок `RobustToolbox`
- [ ] нет мусорного reformat
- [ ] порт: источник указан, нет дубля
- [ ] ветка не `main` без команды

## Формат отчёта

```
РЕВЬЮ
- блокер: ...
- дефект: path — кратко
- вопрос: path — что уточнить
- ок: path

ВЕРДИКТ
- коммитить / не коммитить + почему (1–2 строки)
```

Без воды. Без переписывания всего diff.
