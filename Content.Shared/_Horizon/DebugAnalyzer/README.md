# Дебаг-анализатор

Ручной сканер, который показывает всё, что игра знает о живом существе: здоровье, голод, жажду, нужды животных,
рост и т.д. Предназначен для отладки и админов, в обычной игре не выдаётся.

Этот файл описывает устройство и то, как перенести анализатор в другую игру или движок.

## Как пользоваться

1. Заспавнить сущность `DebugAnalyzer`.
2. Кликнуть предметом по существу с `MobState`, либо использовать в руке, чтобы просканировать себя.
3. Откроется окно, отчёт обновляется раз в секунду (`UpdateInterval`).
4. Слежение прекращается, когда существо удалено, дальше `MaxScanRange` (по умолчанию 5 тайлов) или окно закрыто.

Настройки в YAML, компонент `DebugAnalyzer`: `updateInterval`, `maxScanRange` (`null` значит без ограничения).

## Архитектура

Три независимые части, связанные только моделью отчёта:

```
 существо ──► [Сборщик отчёта] ──► DebugAnalyzerScannedMessage ──► [Окно]
              (сервер, знает игру)    (данные, без логики)         (клиент, только рисует)
```

| Часть | Файл | От чего зависит |
|---|---|---|
| Модель отчёта | `Shared/_Horizon/DebugAnalyzer/DebugAnalyzerReport.cs` | ни от чего, только сериализация |
| Сбор данных | `Server/_Horizon/DebugAnalyzer/DebugAnalyzerSystem.cs` | компоненты игры (здоровье, голод, husbandry) |
| Окно | `Client/_Horizon/DebugAnalyzer/DebugAnalyzerWindow.cs` | UI-фреймворк движка |
| Предмет и его UI | `Shared/.../DebugAnalyzerComponent.cs`, `DebugAnalyzerBoundUserInterface.cs`, `debug_analyzer.yml` | ECS и UI движка |
| Тексты | `Resources/Locale/{en-US,ru-RU}/_Horizon/debug-analyzer.ftl` | система локализации |

Сервер собирает отчёт потому, что часть значений клиенту не передаётся (например точные `Satiety`/`Hydration`
в `AnimalNeedsComponent`, клиент знает только уровень). Поэтому окно ничего не читает из сущности само, оно
показывает только то, что пришло в сообщении.

### Модель отчёта

```
DebugAnalyzerScannedMessage
├─ Target        id существа
├─ TargetName    имя
└─ Sections[]    DebugAnalyzerSection
   ├─ Title      id локализации заголовка
   └─ Rows[]     DebugAnalyzerRow
      ├─ Label     id локализации подписи (если это не id, показывается как есть)
      ├─ Value     готовая строка
      ├─ Fraction  0..1 или null; если задано, под строкой рисуется полоса
      └─ Severity  Normal / Warning / Critical, цвет значения и полосы
```

Значения (`Value`) всегда готовые строки с инвариантной культурой (`0.#`), перечисления выводятся по имени
(`Starving`, `Low`, `Alive`). Это сделано намеренно: отладчику нужны точные внутренние имена, а не красивые тексты.
Переводятся только подписи и заголовки. Исключение: названия типов урона приходят уже переведёнными сервером.

### Какие секции и откуда берутся данные

Секция добавляется, только если у существа есть нужный компонент.

| Секция | Источник в SS14 | Что показывает |
|---|---|---|
| Общее | `MetaData`, `MobState`, `AnimalSex` | прототип, id, состояние, пол |
| Здоровье | `Damageable`, `MobThresholds`, `Temperature`, `Bloodstream` | урон / порог смерти, пороги, урон по типам, температура, кровь, кровотечение |
| Голод | `Hunger` (ванильный) | значение / максимум, порог, расход в минуту |
| Жажда | `Thirst` (ванильный) | то же |
| Нужды животного | `AnimalNeeds` (Husbandry) | сытость и гидратация: значение, уровень, расход, порог поиска |
| Туалет | `Defecation` (система трубопровода и дефекации) | желание сходить в туалет (значение / порог аварии), порог, начало позывов, базовый рост в минуту |
| Навоз | `ManureProducer` (Husbandry) | кусков на единицу питательности, остаток до следующего куска, что оставляет |
| Рост | `Growth` (Husbandry) | стадия, время до следующей, масштаб, мясо, цена |
| Езда верхом | `Rideable` (Husbandry) | всадник |

Пороги серьёзности (`Severity`) задаются в коде сборщика: урон ≥ 40% порога смерти это Warning, ≥ 75% это
Critical; кровь < 90% Warning, < 60% Critical; уровни голода, жажды и нужд по своим порогам.

## Как добавить строку или секцию

1. В `DebugAnalyzerSystem` добавить строку в нужный `Build*` (или новый `Build*` и вызов `TryAdd` в `SendReport`):
   ```csharp
   rows.Add(new DebugAnalyzerRow(L("my-label"), Fmt(value), Fraction(value, max), severity));
   ```
2. Добавить `debug-analyzer-my-label` в оба `.ftl`.
3. Клиент менять не нужно.

`L("x")` даёт id `debug-analyzer-x`.

## Перенос в другую игру

Переносимо без изменений (чистые данные и идея):
- Модель отчёта: сообщение с секциями, строками, долей 0..1 и серьёзностью. Это обычный DTO, его можно
  переписать на любой язык и любой сетевой слой.
- Разделение на «сборщик на сервере, рисовалка на клиенте».
- Список секций и формулы серьёзности, то есть что именно показывать и когда подсвечивать.

Надо переписать под новый движок (адаптер):
1. **Сборщик.** Методы `Build*` читают компоненты SS14. В новой игре оставить те же секции, заменив чтение
   `HungerComponent`, `DamageableComponent` и т.д. на свои источники. Форма результата (`Section`/`Row`) остаётся.
2. **Доставка.** `DebugAnalyzerScannedMessage` передаётся через BoundUserInterface SS14. В новой игре это любой
   канал «сервер → клиент, адресованный открытому окну».
3. **Окно.** `DebugAnalyzerWindow` строит Label, ProgressBar и ScrollContainer из UI SS14. Логики в нём нет,
   только раскладка: заголовок секции, строка «подпись — значение», полоса под строкой, если есть `Fraction`.
4. **Предмет.** `DebugAnalyzerComponent` + YAML: взаимодействие с целью, слежение за дистанцией и закрытие
   окна. В другой игре это может быть админ-команда или горячая клавиша, модель отчёта от этого не меняется.
5. **Локализация.** Ключи `debug-analyzer-*`, формат Fluent; перенести как есть или заменить системой новой игры.

Зависимости Husbandry односторонние: анализатор знает про Husbandry, но Husbandry про анализатор не знает. Если
модуль Husbandry переезжает отдельно, анализатор можно не брать; без него вылетают только секции «Нужды животного»,
«Рост» и «Езда верхом».

## Известные ограничения

- Окно пересоздаёт все строки при каждом обновлении. Для отладки раз в секунду это нормально, но не проверялось,
  сбрасывается ли при этом прокрутка в игре.
- Сканируются только сущности с `MobState`.
- Спрайт предмета временный: копия анализатора здоровья в `Textures/_Horizon/Objects/Devices/debug_analyzer.rsi` (состояния `icon`, `analyzer` на 12 кадров, `analyzer-inhand-left` и `-right`, список ассетов в разделе 11 README Husbandry).
- Значения считаются на момент сборки отчёта; между обновлениями они не экстраполируются.
