# SoundCues: звуки по сигналам

Общий модуль: на любую сущность вешается компонент `SoundCues` с таблицей «сигнал (cue) → звук». Системы про звуки ничего не знают: они сообщают, что произошло (`PlaySoundCueEvent`), а что именно слышно, решает таблица сущности. Нет сигнала или звука в таблице — тишина.

Модуль ни от чего в `_Horizon` не зависит. Husbandry использует его через тонкие привязки (`Husbandry/Sounds/AnimalSoundBindingsSystem`), и так же его может подключить любой другой модуль.

---

## 1. Как это работает

```
любая система: RaiseLocalEvent(uid, ref new PlaySoundCueEvent(cue, user))
  SoundCueSystem на сущности:
    нет компонента SoundCues или cue в его таблице  ─► тишина (так задумано, звуки есть не у всех)
    идёт кулдаун cue                                ─► тишина
    звука нет в ресурсах (файл, коллекция, пустая)  ─► тишина и одно предупреждение в логе на каждую проблему
    иначе SharedAudioSystem.PlayPredicted(sound, uid, user), запоминает, что cue сейчас играет

любая система: RaiseLocalEvent(uid, ref new StopSoundCueEvent(cue))
  ─► обрывает звук этого cue, если он ещё играет (прерванное жевание), иначе ничего
```

**Клиент и сервер.** Сервер играет для всех в зоне видимости. Клиент подключается, только если событию передан `User`: так делается с тем, что клиент предсказывает сам (посадка верхом), его игрок слышит звук сразу, а сервер ему свою копию не шлёт. Событие без `User` клиент игнорирует, иначе звук был бы слышен дважды. Что поднимается только на сервере (еда), поднимается без `User`.

## 3. YAML

```yaml
# имя сигнала: что случилось, а не что слышно
- type: soundCue
  id: EatStarted

# на сущности
- type: SoundCues
  cues:
    EatStarted:
      sound:
        collection: HorseEat     # или path: /Audio/...
        params:
          volume: -3             # громкость и питч задаются тут же
      cooldown: 1                # секунды: повтор раньше игнорируется, по умолчанию 0
```

Звуки: **mono OGG** (позиционный звук, подробности в README Husbandry, раздел 11).

## 4. Как добавить сигнал

1. Объяви его: `soundCue` в YAML. Имя по событию (`Mounted`, `EatStarted`), не по звуку.
2. Подними там, где это случилось: `PlaySoundCueEvent` на сущности. Если событие уже есть у модуля, добавь подписку в его привязки (образец: `AnimalSoundBindingsSystem`), чтобы сам модуль звуков не знал. Если сигнал предсказывается клиентом, передай `User`, то есть сущность, чей клиент предсказал.
3. Укажи звук в таблице сущности. Нет записи в таблице — тишина, ломать ничего не нужно.
4. Если звук нужно оборвать (длинный, на время действия), подними `StopSoundCueEvent` на отмену.

Если имя сигнала используется в C# (`ProtoId<SoundCuePrototype>`), YAML-линтер проверит, что он объявлен.

## 5. Что бывает при ошибках

| Ситуация | Что происходит |
|---|---|
| у сущности нет `SoundCues` или cue нет в таблице | тишина, без записи в логе |
| идёт кулдаун | тишина |
| файла нет, коллекции нет или она пустая | тишина и один `Warning` на каждую проблему (не на каждое воспроизведение) |

Исключений нет: движок сам бросает исключение на неизвестную коллекцию (`SharedAudioSystem.ResolveSound`), поэтому `SoundCueSystem` проверяет звук до воспроизведения (`GetProblem`).

Тихо только в игре. Тесты, наоборот, должны замечать пропавший звук: `SoundCuesTest.EveryCueCanBePlayed` проходит по таблицам всех прототипов. Тесты проекта вдобавок падают на любом `Warning` в логе, поэтому тест, который нарочно проигрывает битый звук (`MissingSoundStaysSilent`), на время снижает порог до `Error`.

## 6. Ограничения

- **Компонент не сетевой:** таблица берётся из прототипа и есть у каждого клиента (как и сами звуки). Объявляй `SoundCues` в самом прототипе. Компонент, добавленный сервером на лету (например, через `components` стадии роста), клиент не знает, и предсказанный звук, который клиент должен сыграть сам, пропадёт.
- **Только разовые звуки по событию.** Звуков по состоянию («ржёт, пока голодна») и по таймеру нет. Их можно добавить отдельной системой, которая поднимает `PlaySoundCueEvent` по состоянию, таблица и защита остаются как есть.
- **Один cue — один звук одновременно в учёте:** если cue сыграл ещё раз, пока предыдущий звучит, предыдущий доиграет, но остановить его уже нельзя (`Playing` помнит последний).
- Звук всегда на сущности (позиционный), глобальных звуков нет.
- Нет выбора звука по условию (стадия роста, пол): таблица одна на сущность.

## 7. Как перенести в другую игру

Остаётся идея: таблица «сигнал → звук», события вместо прямых вызовов, проверка звука перед воспроизведением, кулдаун. Заменяется то, что берётся у движка:

| Что | Где | Чем заменить |
|---|---|---|
| `SharedAudioSystem.PlayPredicted`, `Stop` | `SoundCueSystem` | воспроизведение звука на объекте, остановка |
| `IResourceManager.ContentFileExists`, `SoundCollectionPrototype` | `SoundCueSystem.GetProblem` | проверка, что файл или набор звуков есть |
| `SoundSpecifier` (файл или коллекция, `params`) | `SoundCueDef` | ссылка на звук с громкостью |
| прототип `soundCue` | `SoundCuePrototype` | просто строковый ключ |
